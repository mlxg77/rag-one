# rag-one v2.5 最终实施报告

报告日期：2026-09-27  
最终状态：**v2.5 工程候选版；工程与检索验收通过，生成质量未达到正式发布门槛。**

## 结论

v2.5 计划中的主体工程改造已经完成，自动化测试、数据集校验、索引一致性与可复现性检查均通过。冻结配置 `800/150 + hybrid_rerank` 已直接执行一次 15 题 Holdout 终验。

Holdout 的检索指标全部通过，但人工严格检查发现：系统在已经召回完整证据时仍会过度拒答或遗漏关键事实。15 题中约 10 题完整正确，严格答案完整率为 66.7%，未达到正式版本的质量要求。因此，本版本不能宣称“v2.5 质量验收通过”，应继续标记为工程候选版。

## 已完成的工程工作

- 目录迁移为可安装的 `src/rag_one` 包，删除旧 `src.*` 和两个独立 ingest 入口。
- 向量与 BM25 使用同一不可变版本、manifest 和原子 active pointer 发布，保留旧版本用于回滚。
- 状态命令严格核对语料、切分 ID、向量 ID、BM25 ID、模型、依赖和 Git 状态。
- 将 32 题 regression 与 15 题 holdout 物理分离，并为多证据问题建立 evidence groups。
- 增加稳定证据锚点，避免 chunk 参数变化造成序号 ID 漂移。
- 检索评估记录 Any-hit、MRR、证据组、完整证据、相邻块、来源数、上下文字符和复现 metadata。
- C1 Prompt 加入“不可信资料边界”和“最少直接引用”，并检查越界引用及拒答带引用。
- Reranker 会拒绝缺失、数量不足、非对象、重复/负数/越界 index 和非有限分数等异常响应。
- editable install 已验证可从项目外目录导入 `rag_one 2.5.0`。
- 自动化测试共 113 项，全部通过。
- regression 32 题和 holdout 15 题的数据集格式校验通过。
- 当前活动索引状态校验通过：`800/150`、111 个 chunk、BM25 1515 个词项。

## Holdout 使用纪律

该 15 题 Holdout 已在冻结候选上执行一次，现已视为消费。后续不得使用这 15 题调整 Prompt、阈值、检索参数或业务逻辑后，再把重复运行结果称为独立终验。

如果继续修复生成端，应使用 regression 和新增开发题定位问题；修复完成后另建一套未参与开发的新盲测集，才能重新进行正式终验。

## 已知限制与后续风险

- 生成端存在过度拒答：即使上下文包含完整证据，也可能回答“无法确定”。
- 多事实问题可能只提取部分证据，导致答案不完整。
- 引用语义支持性仍需人工判定，结构检查只能发现编号类错误。
- active pointer 是原子的，但没有跨进程发布锁，目前只支持单机串行构建。
- 旧索引用于回滚，尚未提供带保留策略的清理命令。
- 证据锚点依赖语料原文；语料改版时必须同步审查。
- PDF 只进行文本提取，不包含 OCR、表格或版面专项处理。
