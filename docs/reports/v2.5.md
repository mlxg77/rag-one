- 报告日期：2026-09-27
- 最后更新：2026-09-28
- 版本定位：收敛、加固与验收，不新增检索功能
- 最终状态：**已完结（学习项目 / 内部演示版，非生产正式发布版）**

## 1. 执行摘要

v2.5 的主体工程已经完成：项目结构、双索引版本发布、回滚、状态验证、评估集隔离、复现信息和异常测试均已落地，115 项自动化测试全部通过。

生成端经过 C1—C4 四轮迭代。冻结候选 `800/150 + hybrid_rerank + v2.5-c4-focused-completeness` 在 32 题 Regression 上达到答案完整率 90.63%、严格引用准确率 100%、拒答准确率 100%、幻觉 0，满足冻结门槛。随后新建 20 题盲测并只运行一次。

新盲测答案正确率为 95%，严格引用准确率为 84.21%，并出现 1 个明确错误事实。项目负责人接受这一结果作为学习项目和内部演示版本的收尾质量，决定不再继续消耗新盲测集追求小幅指标提升。因此 v2.5 正式完结，但该决定不等于生产质量门槛已经全部通过。

## 2. 背景与范围

### 2.1 v2.0 遗留问题

- 功能完成、测试通过、质量达标和学习验收混在同一个“完成”状态中；
- Chroma 与 BM25 可以分别替换，存在半发布和版本不一致风险；
- 评估结果缺少语料、索引、参数、模型和代码版本等复现信息；
- 不同 chunk 配置直接复用序号 ID，会造成标注语义漂移；
- regression 与最终验收集没有严格分离；
- 多证据完整性、引用结构、异常响应和失败恢复测试不足；
- 运行代码、实验记录和当前使用说明逐渐混杂。

### 2.2 本版本范围

v2.5 只处理工程可信度、实验可信度、引用质量和学习验收。

以下内容明确不属于 v2.5：Query Rewriting、Multi-Query、多轮对话、Agent、LangChain/LangGraph、父子块检索、OCR、多模态、知识图谱、权限系统、微服务和分布式部署。

## 3. 工程交付

### 3.1 包与目录结构

- 运行代码迁移到可安装的 `src/rag_one/` 包；
- 删除旧 `src.*` 入口和两个独立 ingest 入口；
- `scripts/` 负责构建与运维，`evaluation/` 负责实验，`tests/` 分为单元和集成测试；
- 文档按 `plans / reports / experiments / decisions / notes` 分层；
- editable install 已验证可从项目外目录导入 `rag_one 2.5.0`。

详细结构见 `docs/project-structure.md`。

### 3.2 双索引版本发布

- Chroma 与 BM25 使用同一个不可变版本和 manifest；
- 构建、写入和校验全部成功后，才原子替换 `active-index.json`；
- 失败时保留旧活动版本，已完成候选可供诊断；
- 支持明确回滚到已有旧版本；
- 状态检查核对语料、chunk ID、向量 ID、BM25 ID、模型、依赖和 Git 状态。

### 3.3 评估与复现

- 32 题 regression 与 15 题 holdout 物理分离；
- 使用文本证据锚点解决不同 chunk 配置下的 ID 漂移；
- 多证据问题使用 evidence groups 和完整证据指标；
- 评估记录 Recall、MRR、证据组、完整证据、上下文字符、Token、延迟和复现 metadata；
- Reranker 对缺失、数量不足、非对象、重复、负数、越界 index 和非有限分数等异常响应进行校验；
- C1 增加“不可信资料边界”和“最少直接引用”；C2—C4 继续增加证据优先、完整性清单、同义场景识别、拒答边界和逐事实引用约束；
- 拒答结构校验改为只把完全等于固定拒答句的答案识别为完全拒答，避免把“资料未规定，但可给出确认渠道”的部分回答误报为拒答带引用。

## 4. 实验与质量结果

### 4.1 Chunk 离线实验

在固定语料和 regression 上完成五组 BM25 离线预检：

| 配置 | Chunk 数 | R@5 | MRR@10 | 完整证据@5 |
|---|---:|---:|---:|---:|
| 600/150 | 164 | 93.5% | 0.661 | 93.5% |
| 800/150 | 111 | 96.8% | **0.689** | 96.8% |
| 1000/150 | 90 | 96.8% | 0.635 | 96.8% |
| 800/80 | 109 | 96.8% | 0.673 | 96.8% |
| 800/220 | 128 | 96.8% | 0.678 | 96.8% |

`800/150` 的 MRR@10 最高，因此作为 v2.5 冻结配置。真实 Embedding/Rerank 四模式对比后来被主动取消，所以它只能称为“有离线证据支持的工程选择”，不能称为完整链路的全局最优参数。

### 4.2 生成端迭代

| 候选 | 主要变化 | Regression 人工结论 |
|---|---|---|
| C1 | 最少直接引用与资料不可信边界 | 32 题完整运行；q09、q11、q12、q13、q19 错误拒答 |

## 5. 失败归因与数据使用边界

### 5.1 失败归因

```text
正确证据进入 Top-5
        ↓
证据被送入 Prompt
        ↓
模型没有稳定使用全部证据
        ↓
错误拒答或遗漏关键事实
```

Regression 阶段的主要瓶颈位于生成/决策层。新盲测进一步暴露两类泛化问题：一是等价证据存在但证据锚点未命中导致的检索标注漏召回；二是边界数值判断和引用选择仍不稳定。不能再把问题完全归因于生成层，也不能宣称检索在新问题上始终 100%。

自动结构检查只能证明引用编号合法，不能替代答案正确性、完整性和引用语义支持性的人工判断。

### 5.2 Holdout 使用边界

原 15 题 Holdout 和新 20 题盲测都已执行并查看结果，均已消费。后续不得根据逐题结果调整 Prompt、阈值、检索参数或业务逻辑后，再把重复运行结果称为独立终验。

如果继续修复 b10、b17、b19 所代表的问题，只能把问题类型转入 Regression 或新增开发题。新候选冻结后，必须再建立另一套未参与开发的新盲测集。

## 附录 A：核心概念复盘

以下内容用于学习核对，不代表学习者已经完成验收：

- BM25 的词频项使匹配词出现更多时得分上升，并通过饱和避免无限线性增长；IDF 提高稀有词权重；长度归一化避免长文仅因词多占优势。
- 向量相似度与 BM25 分数的量纲和分布不同，直接相加可能让数值尺度而非质量决定结果。RRF 只使用名次，绕开分数标定问题。
- RRF 的 `k` 越小，榜首名次差异越重要；越大，名次贡献越平缓，更强调多路共识。
- Embedding 是双塔检索，可预计算文档，适合宽召回；Reranker 联合读取问题与候选，交互更充分但成本更高，只适合小候选池。
- Any-hit 只证明至少一个相关块进入 Top-K；多事实问题还需要检查每组必要证据是否完整。
- regression 可以反复用于开发；holdout 只用于冻结候选的最终泛化估计。
- 严格引用准确率按整道答案判定；引用块级精确率按支持块数除以全部引用块数计算。
- 定位错误时应依次检查召回、排序、Prompt 上下文和生成结果，不应把所有错误直接归因于模型。
