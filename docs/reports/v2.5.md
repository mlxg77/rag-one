## 1. 执行摘要

v2.5 的主体工程已经完成：项目结构、双索引版本发布、回滚、状态验证、评估集隔离、复现信息和异常测试均已落地，113 项自动化测试全部通过。

## 2. 背景与范围

### 2.1 v2.0 遗留问题

- 功能完成、测试通过、质量达标和学习验收混在同一个“完成”状态中；
- Chroma 与 BM25 可以分别替换，存在半发布和版本不一致风险；
- 评估结果缺少语料、索引、参数、模型和代码版本等复现信息；
- 不同 chunk 配置直接复用序号 ID，会造成标注语义漂移；
- regression 与最终验收集没有严格分离；
- 多证据完整性、引用结构、异常响应和失败恢复测试不足；
- 运行代码、实验记录和当前使用说明逐渐混杂。

### 2.2 本版本范围

v2.5 只处理工程可信度、实验可信度、引用质量和学习验收。

以下内容明确不属于 v2.5：Query Rewriting、Multi-Query、多轮对话、Agent、LangChain/LangGraph、父子块检索、OCR、多模态、知识图谱、权限系统、微服务和分布式部署。

## 3. 工程交付

### 3.1 包与目录结构

- 运行代码迁移到可安装的 `src/rag_one/` 包；
- 删除旧 `src.*` 入口和两个独立 ingest 入口；
- `scripts/` 负责构建与运维，`evaluation/` 负责实验，`tests/` 分为单元和集成测试；
- 文档按 `plans / reports / experiments / decisions / notes` 分层；
- editable install 已验证可从项目外目录导入 `rag_one 2.5.0`。

详细结构见 `docs/project-structure.md`。

### 3.2 双索引版本发布

- Chroma 与 BM25 使用同一个不可变版本和 manifest；
- 构建、写入和校验全部成功后，才原子替换 `active-index.json`；
- 失败时保留旧活动版本，已完成候选可供诊断；
- 支持明确回滚到已有旧版本；
- 状态检查核对语料、chunk ID、向量 ID、BM25 ID、模型、依赖和 Git 状态。

### 3.3 评估与复现

- 32 题 regression 与 15 题 holdout 物理分离；
- 使用文本证据锚点解决不同 chunk 配置下的 ID 漂移；
- 多证据问题使用 evidence groups 和完整证据指标；
- 评估记录 Recall、MRR、证据组、完整证据、上下文字符、Token、延迟和复现 metadata；
- Reranker 对缺失、数量不足、非对象、重复、负数、越界 index 和非有限分数等异常响应进行校验；
- C1 Prompt 增加“不可信资料边界”和“最少直接引用”，并检查引用越界及拒答带引用。

## 5. 失败归因与数据使用边界

### 5.1 失败归因

```text
正确证据进入 Top-5
        ↓
证据被送入 Prompt
        ↓
模型没有稳定使用全部证据
        ↓
错误拒答或遗漏关键事实
```

因此，当前主要瓶颈位于生成/决策层，而不是 Embedding、BM25、RRF、Reranker 或 chunk 参数。

自动结构检查只能证明引用编号合法，不能替代答案正确性、完整性和引用语义支持性的人工判断。

### 5.2 Holdout 使用边界

现有 15 题 Holdout 已执行并查看结果，现已消费。后续不得根据这些逐题结果调整 Prompt、阈值、检索参数或业务逻辑后，再把重复运行结果称为独立终验。

如果继续修复生成端，只能使用 regression 或新增开发题；新候选冻结后，需要建立一套未参与开发的新盲测集。

- 生成端存在过度拒答和多事实遗漏；
- 引用语义支持性仍需人工判定；

- 证据锚点依赖原文，语料改版时必须同步审查；
- PDF 只支持文本提取，不支持 OCR、图片、表格和版面解析。

## 附录 A：核心概念复盘

以下内容用于学习核对，不代表学习者已经完成验收：

- BM25 的词频项使匹配词出现更多时得分上升，并通过饱和避免无限线性增长；IDF 提高稀有词权重；长度归一化避免长文仅因词多占优势。
- 向量相似度与 BM25 分数的量纲和分布不同，直接相加可能让数值尺度而非质量决定结果。RRF 只使用名次，绕开分数标定问题。
- RRF 的 `k` 越小，榜首名次差异越重要；越大，名次贡献越平缓，更强调多路共识。
- Embedding 是双塔检索，可预计算文档，适合宽召回；Reranker 联合读取问题与候选，交互更充分但成本更高，只适合小候选池。
- Any-hit 只证明至少一个相关块进入 Top-K；多事实问题还需要检查每组必要证据是否完整。
- regression 可以反复用于开发；holdout 只用于冻结候选的最终泛化估计。
- 严格引用准确率按整道答案判定；引用块级精确率按支持块数除以全部引用块数计算。
- 定位错误时应依次检查召回、排序、Prompt 上下文和生成结果，不应把所有错误直接归因于模型。
